# 開發 EMV Part I

2018 年 9 月 4 日

ID TECH 生產並銷售各式各樣的支付裝置，而如今幾乎所有產品都支援「晶片卡」（或稱「智慧卡」）。使用晶片卡完成的支付交易通常被稱為「接觸式 EMV」，有時簡稱為「EMV」。（EMV 當然代表 Europay、MasterCard 和 Visa——這三大卡組織所組成的聯盟。）

在產業術語中，所謂的 EMV 交易，是指符合《EMV 晶片卡支付系統整合電路卡規範》要求的交易。要完全理解這套規範需要花費相當多時間。ID TECH 致力於讓 EMV 相容性成為開發者容易達成的目標，因此提供免費工具、SDK 與示範程式，協助整合商加速上市。

## EMV：從哪裡開始？

多數新的 ID TECH 客戶都具有相當良好的技術背景。不過在專案中，客戶對 EMV 的熟悉程度仍有差異：有些熟悉 MSR，有些接觸過 EMV 但不熟非接觸式，也有人是第一次接觸 EMV。

通常建議先閱讀白皮書《使用 Universal SDK 的 EMV 交易》，先掌握交易流程與關鍵事件。流程每一個階段中，讀卡機都會透過 ISO-7816 定義的低階通訊協議與卡片晶片溝通。大部分邏輯封裝於 EMV Level 2 Kernel，開發者通常是對讀卡機或 SDK 發送指令，而不是直接對卡片下指令。

## 與讀卡機通訊

向讀卡機發送指令通常有兩種方式：

- 直接與裝置連線（USB / RS-232），發送韌體指令。
- 使用高階語言 SDK（C/C++、C#、Objective-C、Java、Swift）透過函式庫發送底層命令。

第二種方式上手通常較快，但可能綁定語言與作業系統；第一種方式彈性較高，但必須自己處理更多底層連線與命令細節。

一筆接觸式 EMV 交易（插卡）通常分為三個階段：

- Start Transaction（開始交易）
- Authenticate Transaction（驗證交易）
- Complete Transaction（完成交易）

交易過程中，Kernel 會在不同節點把控制權交還給呼叫端。不同節點可取得的 TLV 資料不同，開發者需在當下擷取。舉例來說，Tag 57（Track 2 Data）可能只在前段出現，後段不再提供。

## EMV 中的密碼學憑證（Cryptogram）

EMV 交易中的關鍵資料之一是 Tag 9F26（Application Cryptogram）。接觸式交易通常會產生兩次 cryptogram（Gen AC 前後各一次）。

cryptogram 的核心價值在於證明「真實晶片卡確實參與了此交易」，並對交易資料提供不可否認的加密驗證。授權端可根據其有效性判定交易是否批准。這也是 EMV 相較磁條更安全的關鍵。

在下一篇文章中，我們將繼續探討不同類型 cryptogram 的意義、開發者如何處理，以及它們如何影響交易成功或失敗。
